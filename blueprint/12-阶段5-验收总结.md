# 阶段 5（gateway-worker 混合架构：社交层 + 战斗层直连）验收总结

> 文档定位：阶段 5 端到端验收复盘（组 12，ADR-014/ADR-015 的落地验收口径），非设计文档。
> 验收日期 2026-08-16；环境 WSL / PHP 8.3.32 / Workerman 5.2.2 / gateway-worker 4.0.1 / Redis（127.0.0.1:6379）。
> 交付物：`packages/demo/bin/verify-phase5.php`（一体化验收脚本）、`packages/demo/bin/map-rolling.php`（Map 滚动更新 CLI）。

## 1. 架构转向（ADR-014 修订 ADR-010）

阶段 2 的 ADR-010 定「不引入 gateway-worker，纯自研」；经过阶段 4 实践后转向**混合架构**：

```text
客户端 ──社交连接──> gateway-worker（Gateway 管连接 + Business 无状态业务）
  │                   ├─ 登录、分组维护、信息发送
  │                   └─ 多 Gateway + Business 热更新不断连
  ├─ 战斗连接（直连）──> Map/副本（自研，有状态，帧同步，滚动更新）
  └─ 协调：Redis（登录凭证 token + 战斗服务器注册/发现 + 临时共享状态带 TTL）
```

- **gateway-worker**：登录、地图频道/帮派/队伍分组维护、聊天/组队业务。Business 无状态可热更新（reload 不断连）。
- **Redis**：登录凭证（token 五态）+ 战斗服务器注册/发现 + 临时共享状态（组队/位置快照/掉线标记）带 TTL。
- **Map/副本**：有状态（帧级战斗），不能 reload，用「滚动更新」。
- **铁律：战斗帧同步必须客户端直连 Map，不经过 gateway-worker 转发**（避免高频多一跳开销）。

## 4. 关键决策

1. **token 简化为单 scope `['map']`**：业务只签 `['map']`（auth 初始 + map:enter 续签两处），Map 只 `consume('map')`；token 传递路径仅客户端，切图/重连经 map:enter 重新 issue 一次性凭证（BLOCKER-3），无「旧 token 重放/无凭证进图」缺口。
2. **RPC 链全删**：阶段 4 的服务间 RPC（跨服 TCP + ActorRef + 内部握手）随社交层迁移全部移除，cluster 包收敛为仅注册/发现职责。
3. **组队状态机迁 Redis Lua（并发安全）**：BusinessWorker `count>1` 后原「单进程串行」前提失效，判定逻辑入 Lua 原子读改写（5 脚本）；「一 uid 一队」以 `uid-team:{uid}` 键存在性为唯一判据（BLOCKER-1 TTL 同步续期、BLOCKER-2 建队判队原子、MAJOR-2 cjson 编码）。
4. **map:enter 凭证路径**：per-scope 墓碑下切图/重连无新凭证 → 新增 `map:enter`/`map:entered` 上行申请/下行签发契约，签发与消费一一对应。
5. **滚动更新（新 channelId + stopping 标记）**：新服务启动 → 旧服务 Redis 标记 `stopping` → Business 分配过滤（只选 `serving`）→ 旧服务玩家自然退出/重连自迁移新 channelId → 旧服务销毁。

## 6. 验收脚本使用说明

```bash
# 前置（ADR-015 §4.1 启动铁序）：Redis 127.0.0.1:6379 可用
php packages/demo/gateway-worker/start_register.php   # Register(1236)
php packages/demo/gateway-worker/start_gateway.php    # Gateway(18285)
php packages/demo/gateway-worker/start_businessworker.php  # BusinessWorker(count=2)
php packages/demo/bin/launch.php                      # 后台启动 3 个 Map（18081/18082/18083）
# 端到端验收（8 项，真实多进程链路）
php packages/demo/bin/verify-phase5.php
```

- verify-phase5.php 输出契约：每项一行 `[verify] [PASS|FAIL|SKIP]`；末行 `RESULT` 汇总。
- 脚本收尾自动关闭客户端连接、恢复被标记 stopping 的频道、清理 Redis 测试残留。

## 7. 遗留项

- **Register 端口 1236 被 WSL2 保留端口占用（环境问题）**：WSL2 的保留端口范围会抢占 1236，需 `netsh interface ipv4 add excludedportrange` 或改 Register 端口规避，属环境配置而非代码问题。
- **guild 完整实现后置**：阶段 5 仅 `guild:join`/`guild:leave` 最小两操作 + 键结构占位，完整帮派功能（权限/升级/公告等）后置。
- **副本后置**：副本（dungeon serviceType）仅预留协议位，副本分配（`dungeon:enter`）复用同一 discover 过滤机制，后续阶段实现。
- **Redis Cluster hash tag 约束**：TeamStore Lua 内 `team:{teamId}` 键名动态拼接，demo 单机 Redis 成立；若迁 Redis Cluster 需对 team 相关键统一加 hash tag 保同 slot（阶段 5 不处理，已文档化）。
- **超时迁移策略**：滚动更新不做 Business 主动踢，采用「自然退出 + 运维强制 stop + 重连自迁移」（ADR-015 §7-6 确认口径）。
