# 29 · P17 热更层裁决记录

> 批次：P17 热更层裁决（blueprint/21 阶段 C：先出 ADR 裁决做不做，再立项）。
> 基准：commit e014c00（P16 收官）。
> 裁决：**ADR-026**（`.opencode/context/decisions/ADR-026-热更层裁决.md`）——**不做脚本热更层**。

## 一、裁决摘要

| 候选 | 裁决 | 核心理由 |
|---|---|---|
| Lua embed | **否决** | PHP 生态无可维护的 embed（ext-lua 停在 PHP 7）；双工具链（phpstan/PHPUnit 不覆盖 Lua 侧）、跨 VM 边界成本、沙箱面——「不可信脚本」场景本仓库不存在，代价收益完全失衡 |
| PHP DSL（规则引擎） | **否决** | 自研 DSL = 永久性语言维护负担，表达力天花板低；当前「声明式参数行 + 装配期校验」（SkillDefinition/P11 表驱动范式）已覆盖参数化玩法，逻辑组合需求出现且可量化时再评估 |
| 仅配置热载 + rolling | **采纳（维持并正式化）** | 数值/内容 → P11 配置热载（schema 校验 + 坏表回滚）；逻辑 → 测试 + CI 门禁 + **P16 drain/rolling**（分钟级、连接无损）；紧急止血 → GM 命令面（可扩展） |

**重启条件**（满足其一方可重新立项，见 ADR-026 §5）：分钟级玩法逻辑迭代的硬需求被事故记录证实 /
出现不可信方提供脚本（UGC/多租户）→ 届时评估「隔离进程 + 受限 DSL」而非进程内 embed /
PHP 生态出现维护活跃的沙箱化脚本扩展。
