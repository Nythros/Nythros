## 3. 关键设计决策

- 跨进程 token 落地 Redis：Workerman Linux 下每 Worker 独立 fork 进程，InMemoryTokenStore 进程内存不共享 → gateway 签发 token 在 map 进程必 invalid。
- Lua 原子消费：单 EVAL 脚本内完成「墓碑判定 → GET → expiresAt 判定 → DEL + 写墓碑」，5 进程并发 consume 同一 token 恰一个 Valid。
- 墓碑防重放：消费/移除后写 :tombstone 键（TTL=剩余存活），二次消费判定 Replayed，与 InMemoryTokenStore 语义对齐。
- PHP 侧时钟判定过期：不依赖 Redis 时钟，规避 Windows 侧 Redis 经 localhost 转发的跨机时钟偏差。
- 连接工厂模式：fork 复制 socket fd，多 worker 共享同一 Redis 连接破坏协议 → 传闭包，fork 后各 worker 首次使用时各自建连。

## 4. 问题与根因复盘

| 现象 | 根因 | 修复 |
|---|---|---|
| sync 首轮 FAILED：auth_failed invalid | InMemoryTokenStore 跨进程失效 | 落地 RedisTokenStore |
| login 收到约 7 次重复 login_ok | 客户端 worker 回调内 stopAll() → master 无限重启 worker → 重连风暴 | 改 posix_kill(posix_getppid(), SIGINT) |
| 脚本 Timer::add TypeError 崩溃 | 第三参误传 bool（应为 $args 数组） | 改 Timer::add(..., [], $persistent) |
| count 被钳制为 1 | Windows 遗留 hack min($workerCount,1) | 决策：阶段 2 保持单进程，阶段 4 再放开 |
