# 阶段 5 决策确认与偏差复盘

> 阶段 5 验收完成后、进入下一阶段前。复盘架构转向（纯自研 → gateway-worker 混合）的决策与偏差。

## 1. 决策全景回顾

| 阶段 | 决策/事件 | 性质 |
|---|---|---|
| 性能瓶颈讨论 | region 同步 call 350 倍恶化、resolve/discover O(N) | 阶段 4 遗留 |
| 需求澄清 | 聊天是「分组广播」不是 region | 关键简化，消掉 region 瓶颈 |
| 架构转向 | 引入 gateway-worker（多网关+热更新+动态增减） | 最大决策，修订 ADR-010 |
| 数据边界四步 | 四类状态 / 运行时状态图 / Gateway 分组方案 / ADR-014 | 逐步收敛 |
| 组队纠正 | 组队是「临时 + Redis TTL」不是永久 | 边界澄清 |
| reviewer 前置审（4 轮） | 拦截 3 BLOCKER + 8 MAJOR | 前置审查价值 |
| 实施（组①-⑦） | 依赖→四文件→Social→Lua→删除改造→rolling→验收 | 逐步完成 |
| 代码审查 | PASS（5 MINOR 已处理） | 已闭环 |

## 2. 偏差核查（分四级）

### 级别 A：架构转向导致阶段 4 成果被删除

阶段 4 的 RPC 层（SimpleRpcClient/ActorRef 族/Transport）在阶段 5 全部删除——gateway-worker 架构下社交走 gateway-worker、战斗纯进程内、协调走 Redis，服务间 RPC 不再需要。

教训：**架构决策前置不足**。阶段 4 投入大量精力做的「服务间 RPC 通信」，在阶段 5 的「gateway-worker 混合」方向下整层作废。若「低频社交用现成框架、高频战斗自研」方向在阶段 4 之前明确，RPC 层（内部握手、Fiber 同步等待、跨服传输）可省。

### 级别 B：需求理解前后反复（region 聊天）

阶段 3/4 做了 region 聊天（chat:region_players RPC + AOI 九宫格 + 350 倍瓶颈），阶段 5 澄清「聊天是分组广播不是 region」后整个删除。

教训：**需求理解前置不足**。设计「空间性功能」前，未和用户确认「是空间（AOI）还是逻辑（分组）」语义，导致做反方向。

### 级别 C：Lua 并发正确性的文档推演极限

组队状态机迁 Redis Lua，4 轮前置审查反复发现边界问题（TTL 分叉、TOCTOU、建队漏写条目、ARGV 索引错位、HGETALL 扁平数组）。

教训：**并发正确性靠实现+测试锁定**。复杂并发逻辑不依赖文档推演到完美，文档定「边界矩阵」，真实并发测试（多进程 barrier）才是最终防线。

### 级别 D：蓝图阶段 5 目标偏离

蓝图阶段 5 规划「framework 四基类 + CLI + 插件 + 可玩 Demo」，实际做的是「架构转向」。framework 四基类、CLI、插件机制未做。

这是合理的优先级调整（架构地基比四基类更基础），但需明确：蓝图阶段 5 的「framework + Demo」目标未达成，被「架构转向」替代。

## 3. 未来愿景对照

技术路线：Runtime Kernel → Actor+Scheduler → World → AOI → Event → Network ✓（阶段1-3）；Persistence/Multi Process/Multi Server 单机 ✓（阶段4）；架构转向（gateway-worker 混合）✓（阶段5，蓝图外新增）；Framework 四基类 + CLI + 插件 + 可玩 Demo ✗（蓝图阶段5 未做）；跨机/Cluster/地图分片 ✗（阶段6+）。

铁律未破（战斗直连 Map 铁律守住、World 零依赖、不为未来堆功能）。

## 4. 结论

无方向性偏差。3 条教训（架构决策前置、需求理解前置、并发正确性靠测试锁定）已补进 `.opencode/rules/architecture-design.md`。
