## 2. 实现

- **`benchmarks/stress-play.php`**（新）：混合玩法压测客户端。复用 drill-harness 握手/发送/
  帧解析 + map-codec 二进制片，stream_select 引擎按 **opcode 分流**（0x1 社交 JSON / 0x2 map 二进制）。
  每 bot = **gateway 连接全程保活**（P10 踩坑：登录即关 gw 会触发地图侧 onClose 连坐退队——与
  stress-map 的关闭策略刻意相反）+ 一条 map 二进制连接（迁移时关闭重连）。行为节奏：走位（move-ms）
  + `--transfer-every` 跨图轮转 + `--dungeon-every` 副本往返 + `--team-every` 组队循环（相邻 uid 配对，
  偶数对走 member-leave、奇数对走 leader-disband，两条收尾路径每周期都覆盖）+ `--chat-every` 三 scope
  轮转。已知正确消息序列全部照抄 verify-phase5/transfer（零新造协议，ADR-025 四步迁移闭环：
  map:enter → 关旧 map 导票据 → 新址 auth 消费 → map:join）。
- **drill-harness 泛化**：`drillParseWsBuffer` 从 stress-map 上收共享（stress-map 保留回归用例）；
  `drillSocialFrame`（timestamp 必须数字的信封构造，纯函数）；`drillPlayProbe`（服务端侧玩法发生
  探针：`nythros:transfer:*` 键计数 / `nythros:svc:map` 里 dungeon- 前缀 worker 的 playerCount /
  `nythros:gw:team:*` 键族）；`PLAY_DEBUG=1` 门控的 team 错误原样打印（观测可见性）。
- **soak `--play` 接线**：波次 driver 换成 stress-play（shell_exec 结构不变）；时间线波次记录加
  `driver:"play"` + 8 项玩法计数；波后采样并入 playProbe 读数；`soakPlayVerdict` 纯函数——**「玩法
  静默」判 FAIL**（play 波全零事件 = 协议漂移，绿灯即假灯）；非 play 模式行为逐字节不变（向后兼容）。

## 3. 语义裁决（诚实记录）

- **「退出副本回到进入副本前的位置」按现状不成立**：ADR-025 §3.3 裁决跨图（含副本往返）固定落
  目的图 spawnPoint，异图不搬坐标（`MapServerTransferTest` 锚死）。stress-play 如实断言此现状
  （副本出=attach 成功 + hp/背包恢复，坐标不落断言）。若要真回原位 = 行为变更，需新 ADR，本轮不做。
- 同图重连/换线的坐标恢复（票据同图路径）已有单测覆盖，不在压测重复建设。
- team/chat/transfer **无专属 perf 计数器**（引擎埋点缺口，另议立项），本轮「发生证明」=
  客户端回执计数（权威、逐波）+ playProbe 服务端旁证（transfer 键 / dungeon playerCount / team 键）。

## 4. 开发期实抓缺陷（本轮演练器的价值本身）

1. **fread 已关闭流的崩溃**（stress-play 首跑即崩）：同批 select 中一条 gateway 帧触发迁移
   `fclose` 旧 map 流，本批后续仍持有该资源。修复：读循环 `is_resource` + 流身份双检
   （`(int)$cur !== $sid` 即跳过）。240 并发迁移下必现，6 客户端低并发躲过了冒烟——并发规模
   本身就是测试用例。
2. **soak ABORT 归因被 multibyte 吞掉**（既有代码潜伏 bug，本轮首次真触发 ABORT 才暴露）：
   `"$abort（现场已保留..."` 中全角括号字节落入 PHP 变量名合法集（`[a-zA-Z_\x80-\xff]`），
   变量名解析成 `$abort（现场已保留：` → 归因输出空白。修复 `{$abort}` 界定。
3. **`pkill -f <模式>` 自杀**：清理命令的 bash -c 命令行本身含模式串 → 误杀自己（exit 15），
   连带截断后续写入。规约：pkill/pgrep 模式一律方括号拆分（`soak-watc[h].sh`）。
4. **Redis 队伍残留污染**：跨轮实验的 `nythros:gw:team:*`（TTL 600s）让下轮首波 invite 吃 409。
   `--play` 前置 flushall 是硬要求（launch 脚本已含）。
5. **establish 撞注册表真空**：flushall 后 ≤5s 心跳重注册前 auth 一律 503——503 视作未就绪有界
   重试（重握手，12s 窗口），其余失败不重试。
6. **组队状态机的 ack/notify 竞态**：服务端顺序是先 `sendToGroup(disbanded)` 后回
   `team:ok{action:disband}`——notify 先清 phase 会让 team:ok 门控计数落空（D 恒 0 的根因）。
   裁决：leader 的 disbanded **以 team:ok action 回执为唯一计数点**；notify 只清态；
   `target_offline/team_not_found` 归入良性竞态桶（teamOffline/静默）不污染 teamError。

定位压测器自身（stress-play 240 bot 缓冲）与页缓存（worker RSS 冻结是天然对照组），必要时
soak 的 24h 参数下调 `--min-mem-mb` 或改用内存更大机器，**不要误判为应用泄漏**；

另：`soakPlayVerdict` 的「有发无收不算发生」门控在 11h 下零误报，保留。

## 8. 中途止损双保险（24h 轮上线，防「白跑一天」）

风险定义：若 play driver 在长跑第 N 小时起静默死亡（协议漂移/子进程僵死/会话连坐），
终局 `soakPlayVerdict` 只能事后宣告假绿——24h 里玩法矩阵一栏报废。稳定性证据
（RSS/auth/dropped/memAvail）不依赖玩法活跃，但发现延迟必须从「明天」压到「小时级」。

| 层 | 载体 | 触发 | 动作 |
|---|---|---|---|
| **B 静默熔断**（进程内） | `soakGuard` + `--play-silence=K`（默认 5，0 关） | 连续 K 个 play 波回执活动全零（有发无收不算发生） | 立即 ABORT 留现场（时间线 `kind:"abort"`），soak 以 FAIL 正常收尾自停栈 |
| **A 每小时巡检**（进程外，只读） | `.zcode/soak-hourly-check.sh` | P1 进程消失无 DONE / P2 日志现 ABORT / P3 波次推进 <30/h / P4 rssTotal 跳变（本形态字节冻结是实证事实）/ P5 dungeon 累计出站字节零增长 / P6 连续 auth 全 0 | 写 `/tmp/soak-alert.flag` + 以 KILLED 落 DONE 标记并终止（含端口族兜底清理）；WARN 项（推进 30-55/h、非满员、memAvail<400MB）只记 `/tmp/soak-health-history.log` 不动作 |

设计要点：① 巡检**零流量**（只 grep 日志 + `redis-cli` 读累计计数器），不污染被测指标；
② P4/P5 的依据是本轮实证的两条不变量（play 负载下 rssTotal 逐字节冻结、dungeon 出站字节
随波次单调），阈值即回归判据；③ B 管进程内可感知的情形（driver 输出异常），A 管进程外
（soak 本体被连坐、卡死）——双层互补，A 对「soak 还活着但已无推进」的场景靠波次计数捕获；
④ 巡检遇 DONE 标记自动退出（自清理）。当前 24h 轮（1440 分钟那次）进程内未含 B（启动早于
合入），由 A 全权看护；**下一轮起 B+A 双保险齐载**。
