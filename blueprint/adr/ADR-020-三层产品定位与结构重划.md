# ADR-020：三层产品定位与结构重划（Engine / Framework / Starter Kit）

> 状态：已接受（2026-08-24，用户批准全部裁决）。
> 取代：ADR-016 §2 的 Demo 定位、ADR-017 §2 决策 6 与 §9.3 分级铁律的「demo 业务类」层级、ADR-019 §1 的 demo 模板定位（详见 §6）。
> 关联：ADR-021（移除 gateway-worker）、ADR-022（序列化双轨制）、architecture.md（本次同步重写）。

## 1. 背景

原定位「阶段式演进的游戏引擎」（架构驱动）在阶段 5 后暴露两个问题：

1. 产品形态含糊：开发者拿到的到底是引擎还是游戏脚手架，取决于读哪份文档；
2. ADR-017 的 framework @internal 白名单被 demo 的 Server / Observability / Persistence / Deploy 四目录实质击穿——demo 已长成半个框架，修补白名单不如重新划层。

本次重定位把上述事实反转为产品结构：承认业务模块属于框架，demo 退回纯接线壳。

## 2. 决策一：三层产品定位

| 层 | 载体 | 职责 | 边界 |
|---|---|---|---|
| Engine | `packages/engine`（单物理包，15 namespace） | 底层运行时：Contracts/Kernel/Scheduler/World/Entity/Actor/Aoi/Event/Network/NetworkWorkerman/Protocol/Security/Persistence/Cluster 等 | 零业务概念；contracts 是唯一出口；实现类 @internal |
| Framework | `packages/framework` | 「电池全含」开发层：Core 矩阵 + 游戏类型模块，覆盖全游戏类型的开箱即用能力 | 只依赖 engine 公开面；不含部署与接线 |
| Starter Kit | `packages/demo` 重定位 | 最小化演示框架全部功能的接线壳：deploy.yaml + launch.php + 最薄玩法组装 | 唯一允许 import 引擎 @internal 的组装点 |

全局技术基线（用户已批准）：仅状态同步（服务器权威），帧同步永久出局；单图频道 5000 人、50ms 基准 tick，tick 频率按房间可配（割草 50ms、射击房间 15-30ms）；客户端承诺仅服务端协议文档；默认纯 PHP，热路径保留扩展替换点（本期不写扩展）；Docker Compose 一等公民。

## 3. 决策二：demo → starter-kit 重定位与业务模块上移

判定原则：**类型无关、零 @internal import、跨游戏可复用 → 上移 `Nythros\Framework\*`；import 引擎内部实现、或属演示专属配置/协议/账号占位 → 留守 starter-kit。**

### 3.2 说明

- 简报所称 ChatService / TeamService 无独立文件：聊天五语义与组队状态机自 ADR-015 起并入 SocialService，随其整体上移。
- MapServer 留守后，framework 经 `VisionBroadcasterInterface` / `ActorLookupInterface` 消费其能力（starter-kit 实现 framework 接口，依赖倒置，方向健康）。
- 上移为机械搬移：namespace 前缀 `Nythros\Demo\` → `Nythros\Framework\`，行为零改动；测试随迁。执行载体 R1（前置 R0 安全网）。

## 4. 决策三：类型模块插件形态策略

- 引擎提供类型无关原语（RoomInstance / AoE 管线等，见 architecture.md §5）；framework 以 **命名空间 + PluginRegistry 插件** 形态承载游戏类型模块（`Framework\Game\Mmorpg`、`Framework\Game\Horde`）。
- 交付分期：mmorpg 与 horde（≤6 人割草）两锚点先行；回合制/MOBA/放置/沙盒按需后补。
- 物理包保持 3 个，不拆类型包——类型模块是 framework 内的命名空间隔离，不是新 composer 包。
- MOBA/FPS 走小房间高频状态同步（复用 RoomInstance + 可配 tick），不引入帧同步。

## 5. 决策四：分期交付原则

个人项目：**架构一次到位，模块分期交付**。每期有独立安全网与门禁（R0-R5 见 architecture.md §6）；禁止为未启动的类型模块预写代码（铁律 8 不变）。

| ADR | 取代内容 | 保留内容 |
|---|---|---|

## 7. 影响 / 后果

- 正面：白名单击穿消解于划层而非修补；framework 成为可独立发布的产品层；starter-kit 回归最小可读样例。
- 代价：R1 一次性搬移约 20 个类 + 全量 namespace 替换 + 测试路径更新；framework 面积扩大，R3 需补齐 Core 矩阵使其名实相符。
- 风险：MonsterActor 等 AI 钩子含具体行为策略，上移后由类型模块参数化（R4 试点验证）；若参数化失败，回退为 starter-kit 子类覆写钩子。
