# ADR-027：协议版本协商（auth 携带 version + 最低版本守卫）

> 状态：已接受

## 背景

线协议的码值"一经发布不得复用/改义"（protocol.md 开头铁律），但握手载荷此前没有客户端版本号——
开服后服务器无法停服升级协议时，没有"老客户端兼容期"的裁决依据：无法区分老客户端与新客户端，
也无法在协议破坏性演进时拒绝过期客户端（而不是让它接入后行为未定义）。

## 决策

1. **auth 帧携带 version**：gateway JSON auth（顶层 + payload）与 Map 二进制 auth（payload 新增
   `version` 字段，PayloadKey = 84，两端码表同步再生成）均携带整型协议版本。
2. **服务器最低版本守卫**：`NYTHROS_MIN_CLIENT_VERSION` 注入最低版本（MapServer
   `setMinClientVersion` / SocialService 构造注入）；未设置 = 守卫不启用，存量客户端零影响。
3. **拒绝语义**：version 缺失/非整型/低于最低版本 → auth_failed（Map 403 `client_version_too_old` /
   gateway 400 同文案）+ 断开；**token 不消费**（与准入守卫同口径），客户端升级后原票据仍可用。
4. **拒绝位置在 authenticate 之前**：旧版本客户端不获得任何认证计算量。

## 理由

- 守卫前置 + token 不消费，使"升级窗口"与"容量准入/drain"共用同一套失败语义，运维心智单一；
- 未设置即关闭，保证 0.x 期间协议演进不强迫所有部署同步配置；
- 版本字段是整型单调值，不做语义化版本比较——协议 wire 格式的兼容性只有"能/不能"两态。

## 影响 / 后果

- 客户端（@nythros/client）auth 全部携带 `version: 1`；自研客户端接入时按 [docs/unity-guide.md](../../docs/unity-guide.md) 同步携带；
- PayloadKey 码表从 83 → 84 字段，TS 生成物同步（`generate-definitions.php`）；
- 未来协议破坏性演进 = bump 最低版本 + 客户端版本字段，回滚 = 调回最低版本。
