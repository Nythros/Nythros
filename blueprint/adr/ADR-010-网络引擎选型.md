# ADR-010：网络引擎选型——只依赖 workerman/workerman，不引入 gateway-worker

> 状态：已接受（阶段 2/3 裁决）

结论：项目只依赖 `workerman/workerman`（^5.2.2）底层事件循环库，不引入 `workerman/gateway-worker`
框架；Gateway 的「连接管理 + 消息路由」职责由自研 GatewayServer 覆盖。

理由：

- network 包定义 ServerInterface / ConnectionInterface 抽象，network-workerman 作为适配层实现，
  底层引擎被隔离在适配层之后，可替换；
- 当前单进程规模未到需要 gateway-worker 的分布式 Gateway / BusinessWorker / Register 模型；
- gateway-worker 的「Gateway 进程」核心职责（连接管理 + 消息路由）已由自研
  WorkermanWebSocketServer + GatewayServer 覆盖。

证据：根 composer.json 与 kernel-workerman / network-workerman 仅声明 workerman/workerman（^5.2.2）；
全库 grep GatewayWorker / BusinessWorker / Register 0 匹配；network-workerman 直接基于
Workerman\Worker 实现 WebSocket 服务，demo 的 GatewayServer / MapServer 在 network 抽象之上组装。
