## 一、交付内容

### 1.1 数据 schema 校验（framework，其余两项的地基）

| 模块 | 说明 |
|---|---|
| `ConfigSchema`（framework/src/Config） | 声明式配置表校验器：标量规则 int/float/string/bool/enum（区间/长度/正则/白名单）+ 结构规则 listOf/shape；shape 字段缺省必填，`optional(默认值)` 放开并回填、`nullable()` 放开 null；**未知字段恒拒绝**（`allowUnknownFields` 显式放开）——内容表字段名拼写错误在装配期暴露。错误为结构化形态 `{path, message}`（路径如 `monsters.2.anchor.x`）。 |
| `ConfigSourceLines`（framework/src/Config） | PHP 数组配置文件的「点号路径 → 源码行号」映射器：tokenizer 扫描短数组语法 `[...]`，键/标量值记首现行号；行号定位逐段向上回退（`monsters.1.anchor.x` → `monsters.1` → `monsters`）。尽力而为的静态扫描：只识别短数组语法，路径定位不到则报错不带行号（**不误标**）。 |
| `ConfigRepository` schema 接线 | `registerFile(key, path, ?schema)` / `registerDirectory(dir, ?schemas)` 可选挂表结构规则：**注册期校验失败 fail-fast**（InvalidArgumentException，消息带配置键/文件/行号）；**热载期校验失败走既有回滚语义**（旧配置保留、不应用不发事件、下次轮询自动重试——修表后自动恢复）；注册产出与热载产出均为 schema 归一化形态（optional 默认值已回填）。 |

### 1.2 技能/掉落表外置（framework 扩展点 + demo 表）

| 模块 | 说明 |
|---|---|
| `SkillRepository::remove/ids` | 热载删除行所需：按 id 摘除（未注册 false）、全量 id 清单。 |
| `DropTable::fromRows` | 行声明构造：`{itemId, weight, minCount?, maxCount?}` → DropEntry（数量区间非法仍由 DropEntry fail-fast）；旧版映射构造不受影响。 |
| `Respawner::registerDeath(overrideMs)` | 逐怪重生延迟：怪物表 `respawnMs` 行参数覆盖全局 `MmorpgConfig.respawnMs`（null/<=0 回落全局）。 |
| `packages/demo/config/{skills,drops}.php` | 参考表：技能五行（fireball/ice_bolt 恒生效；taunt/taunt_aoe/slash_rect 标 `feature: mmorpg`）、掉落条目（bone/potion 恒生效；sword 标 `feature: economy`）。 |
| `GameplayTables`（demo） | 表装配中枢：三表 schema 声明、缺省表、`enabledFeatures()`（env 快照）、feature 行过滤、`applySkills`/`reapplySkills`（启动装配 + 热载重放 diff：增改覆盖、配置源删除行摘除、手写注册技能不受影响）、`buildDropTable`（过滤 + **itemId 引用完整性 fail-fast**——掉落引用未注册物品即装配错误）。 |
| `MapChannelFactory` 装配改线 | 技能注册（原 175-176、332-349 硬编码）与掉落表（原 196）全部改由表驱动；feature 过滤取代 mmorpg/economy 条件块内的硬编码注册。 |

### 1.3 地图/怪物数据外置 + 热载应用面（demo）

| 模块 | 说明 |
|---|---|
| `packages/demo/config/gameplay.php` | 出生点 + 怪物表（id/typeId/maxHp/anchor/patrolRadius/respawnMs?），缺省值与外置前硬编码逐字段一致。 |
| `GameplayConfig`/`MonsterSpawn`（demo） | 表 → 值对象（字段合法性由 schema 保证）。 |

| `MapServer::applyGameplayConfig`（热载） | 出生点换入 + 怪物表 diff：已登记参数热更（锚点/血量/造型/巡逻域/重生延迟，重生侧生效）、新增行立即 spawn（monster:spawned 广播可达）、删除行摘出生登记（死亡登记在重生消费时查空自然作废）；**在场怪物不驱逐**（战斗中移除属破坏性操作，删除行语义 = 不再重生）。 |
| `MapServer::replaceDropTable` / `RoomHub::replaceDropTable`（热载） | drops 表 `config.changed` 原子换入两处掉落源：在场怪物持有旧表引用自然耗尽，新出生/新波次用新表。 |
| `MapServer::spawnPoint()` | 出生点读取口径（热载可变后供装配层/测试消费）。 |
| 出生点优先级 | 配置表 > env `NYTHROS_SPAWN_POINT`（仅配置缺席时生效，P7b 语义保留）> 缺省 (0,0)。 |

### 1.4 配置目录装配（MapChannelFactory 头部前移）

`NYTHROS_CONFIG_DIR` 指向存在的目录时：三表按同名文件挂载并挂 schema（文件缺席的表回落缺省表），其余 `*.php` 沿用 R3 目录注册语义（无 schema）；fork 后各 worker 独立 mtime 轮询（5s，onWorkerStart 内）。热载监听（config.changed → 表级重放）在 MapServer 构造后注册：坏表在 `check()` 内已被 schema 拦截走回滚，到得了监听的必为通过校验的表。

## 三、运行中热载实测（Round B 长驻服务器）

在 Round B 长驻服务器（config 目录启用）上验证 mtime 轮询 → 表级重放链路：

1. `skills.php` 追加一行 `['id' => 'smoke_test', ...]`（php -l 先验语法）→ 8s 内 maps.log 出现
   `[GameplayTables] applied hot-reloaded table: skills`（reapplySkills：smoke_test 注册生效）；
2. 还原 `skills.php` → 再次出现 applied 日志（删除行经 reapplySkills 摘除）。

坏表热载回滚为单测覆盖（ConfigRepositorySchemaTest），不在长驻服务器上污染验收环境。

## 四、边界与后续

- **玩家初始血量未外置**：BasePlayer 的 hp/maxHp=100 为 framework 基类缺省，非 MapChannelFactory 硬编码（blueprint/21 所指「初始血量」= 怪物出生 100/150，已入表）；玩家侧外置需 framework 属性注入点，留待有产品参数输入时一并做。
- **热载语义边界**：怪物表热更对在场怪物不驱逐（重生侧生效）；掉落表热更不回溯在场怪物的持有引用；技能删除行不清理进行中冷却。
- **ItemDefinition 未外置**：物品定义（gold/potion/bone/sword）不在 blueprint/21 P11 范围，sword 的注册条件留守 env 判断、掉落条目已表驱动。
- **E2E 位置断言**：verify-* 脚本对 monster-1/2 锚点的假设与缺省表同值——改锚点做验收时需同步 E2E 目标位（或后续让 verify 脚本读同一配置表，P14 验收脚本公共库候选）。
- P12 的 plugin-guide/state-sync 文档可引用 §3.3（docs/quick-start.md 玩法配置节）。

## 五、遗留记录

- **Round B 首跑 step4/5/8 FAIL（PASS=8 FAIL=3）**：任务进度 Redis 残留（`nythros:gw:quest:<uid>` 跨重启存活）
  污染「初始进度全零」断言——非 P11 回归，清键复跑全绿。三轮验收口径补记为：**每轮全新启动服务器 +
  启动前清任务进度键**。
