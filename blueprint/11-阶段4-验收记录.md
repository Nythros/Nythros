## 3. 关键数据记录

### 3.1 双自愈耗时（kill -9 Map 频道，最终版 2 轮）

- discover('map') 不含被 kill 实例：kill 后 **11.05s（第 1 轮）/ 12.05s（第 2 轮）**（心跳 TTL 15s，0.5s 轮询粒度检测，两轮均 ≤15s 软目标）。
- resolve('map', uid) 自愈为 null：与注册表自愈同刻（11.05s / 12.05s，uid 寻址随注册表自愈，无需 6h TTL）。
- 死实例 uid hash 键被 discover 惰性 DEL；重启恢复后重新 register ≤2s、重新 bind 可寻址。

### 3.2 region 阻塞 Benchmark（MINOR-R7，region-block-benchmark.php）

方法：黑洞端点（tcp://127.0.0.1:19999，收帧不回）经 meta 合并 rpcAddress 注入两个 map 实例 → Chat 的 region call connect 成功后等满 0.5s 超时（完整复现 ADR 9.5 同步 call 阻塞事件循环）；A 每 0.7s 发 region（阻塞阶段收到 503 × 14，与预期 ~14 一致，证明阻塞真实生效）；B 每 200ms 交替 world/private（content 携带 seq），C 收帧记录端到端延迟；基线（A 静默）与阻塞两阶段各 10s 对拍。

| 阶段 | scope | count | p50 | p99 | avg | max |
|---|---|---|---|---|---|---|
| 基线 baseline | world | 35 | 0.66ms | 1.13ms | 0.72ms | 1.13ms |
| 基线 baseline | private | 34 | 0.69ms | 1.23ms | 0.76ms | 1.23ms |
| 阻塞 blocking | world | 25 | **106.39ms** | **406.99ms** | 132.67ms | 406.99ms |
| 阻塞 blocking | private | 25 | **105.09ms** | **407.91ms** | 140.95ms | 407.91ms |

结论：region 同步 call 阻塞期间并发 world/private 消息 p50 恶化约 **150 倍**、p99 恶化约 **350 倍**（峰值 ~0.4s，与 0.5s 阻塞上限同阶）；消息不丢（阻塞期 50/50 全部送达，仅排队延迟）。**ADR 16 章风险条目成立**：「延迟显著恶化」阈值已达到，触发 ADR 9.5 的异步 call 变体评估（后置决策，本阶段不实现，维持结论）。STATS_JSON 原始数据：`{"baseline":{"world":{"count":35,"p50_ms":0.66,"p99_ms":1.13,...},"blocking":{...}}}`（完整值见脚本输出）。

## 5. 实现缺口与安全修复（最终版：全部已修复）

### G-1 服务间 RPC 入站通道桥接（已修复）

各服务的 `SimpleRpcClient::onRequest` 处理器挂在各自进程的 RPC transport 上，但该 transport 是出站客户端（WorkermanAsyncTcpTransport）且从未 connect；服务端 WebSocket 端口的入站帧全部路由到业务 dispatchSafe（客户端协议）。**修复**：各服务 onMessage 中把整帧处理包进原生 Fiber（ADR 9.5 让出事件循环），RPC 入站桥接——已握手内部连接的 `rpc:` 帧从 server onMessage 桥接进 SimpleRpcClient 的 handleIncoming/handleFrame，`chat:region_players` / `team:query_preferred_channel` / `map:cross_ping` 的 onRequest 处理器均可达。ADR 10.1「跨服通道复用 WebSocket 端口」的入站路由落地。

### G-2 Chat/Team 向 ServiceRegistry 注册（已修复）

Chat/Team 服务无 register/heartbeat（meta 无 wsAddress/rpcAddress）→ ① login_ok 的 chat/team 地址恒 null；② Gateway 的 team:query_preferred_channel 恒 Disconnected。**修复**：Chat/Team 按 Map 模式补齐 register/heartbeat（5s 心跳），meta 含 wsAddress/rpcAddress；login_ok 下发真实地址，队长优先可走真实 RPC。

### G-3 transport 协议与 Map meta rpcAddress（已修复）

Map 实例 meta 只有 {mapId, channelId, playerCount, wsAddress}，SimpleRpcClient 寻址依赖 meta.rpcAddress → Chat 的 region RPC 恒 Disconnected（503）。**修复**：Map 注册 meta 补齐 rpcAddress；WorkermanAsyncTcpTransport 支持 ws:// 方案自动选择 WebSocket 客户端协议（自动握手 + 收发自解帧/封帧），出站 call 直接连对端 wsAddress。

### G-4 WorkermanAsyncTcpTransport::send 返回值 bug（已修复）

Workerman 5.2 的 `TcpConnection::send` 成功返回 **null**（仅失败 false），旧实现 `(bool)` 强转 → 恒 false → 出站 call 恒判「传输未连接」Disconnected。**修复**：send 不再依赖底层返回值——「不抛异常 = 已投递」为判据（try/catch 包裹，未连接丢弃返回 false）。

### G-5 Workerman 同 start_file 单实例锁与「重启恢复」冲突（已修复）

Workerman 5 按 start_file 维度做 pidFile+lock 单实例检查：已有实例运行时重新 spawn 同脚本 → "already running" 退出。**修复**：run-worker.php 增加 `--pidFile` 参数——缺省按 type+port 生成独立 pidFile（每个服务实例唯一），deploy.yaml 可显式声明覆盖；崩溃后 spawn 原脚本 + 同 pidFile 即可恢复，不再需要「脚本副本绕过」；验收脚本 spawn 替代进程同步改为直用原脚本（DeployConfig 透传 --pidFile）。

### G-6 run-worker.php 日志闭包作用域 bug（已修复）

onConnect/onClose 的 `echo sprintf('[%s] connect: ...', $options['service'], ...)` 闭包未 `use ($options)` → 每条连接打印两条 Undefined variable Warning。**修复**：闭包补 `use ($options)`，日志归因不再刷屏（不影响功能）。

### MAJOR 安全修复：RPC 内部连接鉴权（rpc:hello 握手）

复用 WebSocket 端口承载 RPC 入站后，任意客户端都可能伪造 `rpc:` 帧直连服务端——**修复**：内部连接握手。① 客户端侧：SimpleRpcClient 注入 serviceId 时，连接建立（onConnect）即发 `rpc:hello{serviceId}`（本服务自己的 serviceId），收到对端 `rpc:hello_ack` 后才投递 call/notify 业务帧；断连后握手状态清位，重连重新握手。② 服务端侧：onMessage 先调 handleHello——`rpc:hello` 是未握手连接**唯一**可接受的 rpc 帧（登记「内部连接集合」connectionId → 对端 serviceId 并回 ack）；其余 rpc: 帧（call/notify/response/error）在未握手连接上一律拒绝（日志归因，不处理）；非 rpc 帧继续走客户端协议。③ 握手登记后的内部连接 markInternal → 限流豁免（MINOR-3）。单测覆盖：未握手 rpc:call 拒绝、握手帧序 [hello, call]、重连不绕过握手（cluster/tests/SimpleRpcClientTest.php、demo/tests/*ServerTest.php）。

### 配套修复：RPC 同步 call 的 Fiber 让出

Workerman 默认 libevent 事件循环的回调不在 Fiber 上下文，同步 RPC call 的阻塞等待（usleep 忙等）会饿死事件循环——异步连接完成与对端回包都无法被处理，恒 Disconnected/Timeout。**修复**：各服务 onMessage 把整帧处理包进原生 Fiber，并注入 Fiber 等待器（`Fiber::suspend` 挂起 + Workerman Timer 续行；非 Fiber 上下文防御性降级 usleep 忙等）——call 挂起时回调即返回，事件循环推进连接/回包，Timer 恢复 Fiber 续行。

### D-1 ADR 18 章双队防护口径勘误（保留，仍有效）

ADR 18 章写「accept(B) → 409 already_in_team」；实现按 ADR 7.3 判定顺序（邀请条目判定 ①② 在 already_in_team ③ 之前）+ MAJOR-7 入队后清除其余邀请 → C accept(A) 后 B 邀请已被清除，accept(B) 实际归 **404 invite_not_found**（与任务书口径「accept(B) 404」一致）。「一 uid 一队」不变量由「③ 409（邀请仍存在时）+ 邀请清除（双保险）」共同保证，行为正确，仅 ADR 18 章描述需勘误（保留 409 分支：若 B 邀请因幂等刷新被重发，30s 内 accept(B) 仍会走 409）。

## 6. 验收脚本使用说明

- RESULT 行契约：`[verify] RESULT: PASSED (PASS=9 FAIL=0 SKIP=0)`；修复后无 SKIP 项（G-1~G-6 全部修复），FAIL=0。
