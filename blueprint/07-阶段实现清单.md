# 阶段实现清单

从零到发布的全阶段任务总清单，按验收门禁推进（不是按时间）。

## 与其他文档的关系

- `03-实施路线图.md`：决定阶段顺序与原则（技术路线、里程碑、铁律、暂缓清单）。
- `04-启动执行清单.md`：阶段 1 的展开，含全部代码示例。
- `05-验收与质量门禁.md`：各阶段的验收标准与质量门禁。
- 本文档：全部阶段的任务清单，是开动代码后按阶段推进的总清单。

阶段 1 直接引用 `04-启动执行清单.md`，不重复代码；阶段 2~6 展开为具体可勾选任务。

## 阶段总览

| 阶段 | 目标 | 对应里程碑（`03-实施路线图.md` 第 4 章） | 进入下一阶段的门禁 |
|---|---|---|---|
| 阶段 1：最小可运行骨架 | 单进程跑通 7 核心最小闭环 | 原型能跑 | 5 帧稳定运行；AOI 反映移动；事件回调触发；World 只依赖 `Nythros\Contracts` |
| 阶段 2：网络与协议 | 接入 Workerman，双客户端实时移动同步 | 引擎核心 | 双客户端移动同步成功；Token 四态；100 连接压测无内存泄漏、无异常断开 |
| 阶段 3：性能工程与调度 | AOI 完善、RegionScheduler 与 CPU 预算、Benchmark 基线 | 引擎核心 | Benchmark 可重复；AOI 错误广播为 0；Actor 状态无并发错误 |
| 阶段 4：持久化与集群 | 存储落地、跨服通信、多进程 | 引擎核心（跨服） | 两个地图服互发业务消息；注册表自愈；跨服消息丢失可解释 |
| 阶段 5：Framework 与 Demo | 四基类 + 插件机制，可玩 Demo | 框架 + Demo | 10 客户端跑通最小 MMO 游戏循环；一条命令启动、一条命令创建 Actor；业务代码不碰 Engine 内部 |
| 阶段 6：发布与生态 | 文档、打包发布、生态起步 | 发布 + 生态 | create-project 后 10~30 分钟启动 Demo；Quick Start 可逐步执行 |

## 阶段 1：最小可运行骨架

单进程、纯 PHP `while` 循环验证核心架构闭环，不引入 Workerman、网络、数据库。

任务与代码见 `04-启动执行清单.md` 的 12 步（第 0 步 + 第 1~11 步），逐项勾选：

- [x] 第 0 步：环境与工具链准备（PHP >= 8.3、Composer 2.x、PHPUnit/PHPStan/PHP-CS-Fixer、.gitignore）——见 04 第 0 步
- [x] 第 1 步：初始化 Monorepo
- [x] 第 2 步：contracts 包定义核心接口
- [x] 第 3 步：kernel 包实现 SystemClock
- [x] 第 4 步：scheduler 包实现 SimpleScheduler
- [x] 第 5 步：entity 包实现 BaseEntity + Position
- [x] 第 6 步：actor 包实现 BaseActor + SimpleActorSystem
- [x] 第 7 步：event 包实现 SimpleEventBus
- [x] 第 8 步：aoi 包实现 GridAOI
- [x] 第 9 步：world 包实现 World + SimpleEntityManager
- [x] 第 10 步：demo 包写 run.php
- [x] 第 11 步：安装与运行

### 验收标准（`04-启动执行清单.md` 第 11 步）

1. `composer install` 成功，path 仓库解析全部本地包。
2. `php packages/demo/run.php` 稳定运行 5 帧无错误。
3. Actor 移动后 AOI 反映新位置（每帧 query 结果与当前位置一致）。
4. 事件回调触发（`player.moved` 每帧输出）。
5. World 只依赖 `Nythros\Contracts` 接口，不依赖任何具体类。
6. `vendor/bin/phpunit` 全部通过（7 个核心包各有最小测试）。
7. `vendor/bin/phpstan` 无错误（level 8）。
8. `vendor/bin/php-cs-fixer fix --dry-run --diff` 通过，格式符合 PSR-12。

### 门禁

全部满足才进入阶段 2：

- 5 帧稳定运行
- AOI 反映移动
- 事件回调触发
- World 只依赖 `Nythros\Contracts`

## 阶段 2：网络与协议

- [x] kernel-workerman 包：Workerman Event Loop 适配 Kernel，用 Workerman Timer 驱动 Clock tick
- [x] network 包：Connection / Session / Server 抽象接口
- [x] network-workerman 包：WebSocket Server 实现、客户端连接管理、连接事件回调
- [x] protocol 包：Message（type/requestId/timestamp/payload）、Serializer、Frame 接口
- [x] JSON Serializer 第一版实现（MessagePack/Protobuf 保持后置，走可替换接口）
- [x] 编解码测试：编码 → 网络 → 解码数据一致；错误包处理不崩溃
- [x] Gateway 服务：登录流程、TokenManager（短 TTL、一次性消费、绑定 uid/map/session、防重放、失败即断开）
- [x] Redis 落地：TTL + Lua 原子消费（RedisTokenStore 落地，consume/remove 走 EVAL 原子脚本）
- [x] 未认证连接处理：超时断开、限流基础设施、慢客户端检测（限流/慢客户端仅基础设施、未在 demo 启用）
- [x] Map Server 实时数据线：客户端持 Token 连接地图服 → 校验 → 绑定 PlayerActor
- [x] 移动同步链路：Client A 移动 → PlayerActor → Cell/AOI → Client B 收到
- [x] 连接断开清理：Actor/Entity/AOI 索引同步移除
- [x] 双客户端移动同步验收测试（以手工验收脚本 sync-client.php 落地，非 PHPUnit）

### 验收与门禁

- 两客户端移动同步成功。
- Token 四态：正常 ✓、过期 ✓、重放 ✗、非法 ✗。
- 100 连接压测 5~10 分钟：无明显内存泄漏、无异常断开。

**阶段 2 验收记录**（2026-08-14，环境：WSL / PHP 8.3.32 / Workerman 5.2.2 / Redis 127.0.0.1:6379）：phpunit 83 测试全绿、双客户端移动同步 PASSED（sync-client.php）、Token 四态全过（含 5 进程并发 consume 恰一个 Valid）、100 连接压测 PASSED，阶段 2 门禁全部满足。

## 使用说明

- 每阶段只勾选本阶段任务；阶段门禁未通过不得进入下一阶段（呼应"按验收结果进入下一阶段，不是按时间"）。
- 阶段内发现架构问题：回到 `01-架构规范.md` 评审，必要时更新 `06-风险与决策记录.md` 的 ADR。
- 阶段 1 已完成的部分按 `04-启动执行清单.md` 逐项勾选。
- 清单粒度：任务可再拆，但不得增加共识之外的模块。
