### 1.3 客户端 JS SDK（nythros-client v0.1）

`packages/client-js/`，零依赖单文件（Node ≥ 22 原生 WebSocket / 浏览器通用）：

| 模块 | 说明 |
|---|---|
| 码表 | FRAME_TYPES（88 帧）/ PAYLOAD_KEYS（83 字段）由 `FrameType::codeMap()` / `PayloadKey::codeMap()` 程序化生成（非手抄），同步铁律写进文件头 |
| `NythrosCodec` | 二进制批量编解码，与 PHP `MapCodec`/`BinaryBatchSerializer` 一一对称（自 js-client-example.js 提炼） |
| `NythrosClient` | 登录链路（gateway JSON 文本 auth + timestamp → token → Map 二进制 auth → entityId）；事件订阅 on/off；`request` 双模式回执（`replyType` 帧类型匹配 / 缺省 requestId 回显匹配——服务器回执语义不统一的实测适配） |
| `NythrosInterpolator` | 插值引擎：事件驱动实体小固定窗口（100ms）；tick 驱动实体（怪物）到达间隔 EMA 自适应窗口（P9 区域降频不顿挫）；消费 `world:tick_rate` 放大自身窗口；**周期视野快照（entity_enter 重发）按权威位置吸附** |

实跑发现并修进 SDK 的三个协议事实（docs/js-client-example.js 均未覆盖）：

1. **网关回帧是二进制帧**（JSON 文本请求 / 二进制回包），需 Blob/ArrayBuffer 归一后再 JSON.parse；
2. **网关校验 `timestamp` 必须为数字**（verify 脚本有发、参考客户端没提）；
3. **回执语义不统一**：部分路由回显 requestId（错误帧/room:ok），部分只发定类型帧不带 requestId
   （quest:list → quest:rows）——SDK request 提供双模式，README 明示选型。

验收示例：`examples/mmorpg-flow.js`——登录链路 → 避险 move（STATE 帧跳过自身的语义注释）→
quest:list 回执（replyType 模式）→ 移动 monster-1 锚点 + 攻击至首条 combat:hit → 插值采样展示
（平滑 vs 权威）→ logout。**Node 实跑 RESULT: PASS**。README（packages/client-js/README.md）覆盖
快速开始 / 语义约定 / checklist。

### 1.4 状态同步指南（docs/state-sync.md）

- 服务器权威模型两条铁律（判定读权威位置 / 渲染读插值位置；绝对坐标无外推）；
- 三类帧语义表（STATE 跳过自身且可丢可合并 / EVENT 关键帧不丢 / STRUCTURE 永不因分频丢弃）+
  客户端推论（自己的 entity_moved 收不到是正常语义；实体表只增删于 enter/leave/monster:spawned）；
- 插值双轨制：事件驱动 vs tick 驱动的窗口策略与理由；`world:tick_rate`（directed 帧）的消费边界
  （只知道自己的分频，别人靠到达间隔实测）；
- 快照重同步自愈链：**周期快照重发的是 `entity_enter` 全量视野**（实读 `RealtimeServer::resyncVision`
  确认，非 entity_moved）——客户端必须把已登记实体的 entity_enter 当纠偏信号吸附，不能当幂等信号忽略；
- 客户端对接 checklist（7 项）。

## 三、边界与后续

- SDK v0.1 无自动重连（断线 pending 全 reject，业务层重建实例）；无 npm 包化（零依赖单文件 +
  README，P12 口径内不做发布工程）。
- 插值仅线性过渡（无预测/回滚，与服务器权威模型一致）；极端降档 5Hz 下 200ms 粒度为结构性表现，
  客户端无特判（P9 预期管理口径）。
- docs/js-client-example.js 保留为协议参考实现（其码表已落后 68 帧/58 字段，文件头已声明以 PHP
  枚举为权威）——后续可选加「指向 SDK」的引导注释，未在本批处理。
- P14 验收脚本公共库抽库后，plugin-guide §6 的手写骨架将被库调用取代（口径不变）。
