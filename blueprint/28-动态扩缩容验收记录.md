# 28 · P16 动态扩缩容验收记录

> 批次：P16 动态扩缩容（blueprint/21 阶段 C：gateway 按 map 负载路由、map worker 动态注册/摘除）。
> 基准：commit 49ce8ef（P15 收官）。

## 一、方案概要

负载路由的地基已存在（ADR-013 服务注册 + ADR-015 selectChannel 最少在线 + P9c busy 元数据），
本批补齐扩缩容的三个缺口，全部零新增协议帧：

| 缺口 | 方案 |
|---|---|
| **容量准入** | map worker 注册 meta 增 `maxCapacity`（env `NYTHROS_MAP_CAPACITY`，0 = 不限量缺省）；gateway `selectChannel` 跳过 `playerCount ≥ maxCapacity` 的实例；auth 侧硬守卫（`admissionRejection` → `map_full` 拒绝，token 不消费可重连其他频道）兜住 select 与 attach 之间的并发窗口 |
| **摘除（scale-in）** | `draining` 生命周期：GM `drain` 命令 → 本实例心跳 meta `status=draining`（心跳 Lua 原子合并，与 `stopping` 同语义）→ `selectChannel` 过滤 draining/stopping → 新会话不再路由，存量连接不受影响；在场玩家归零后由外部编排停机摘除（`bin/server stop` / map-rolling 的 watch 模式）；重复 drain 幂等（error） |
| **扩容（scale-out）** | **零代码**——map worker 直启（`run-worker.php --service=map --mapId=... --channelId=... --port=...`）即自动注册进 Redis registry，gateway discover 即时可见；最少在线选道使新实例（0 玩家）优先接客 |

GM 面：framework 新契约 `GmDrainHandlerInterface`（drain/isDraining，比照 GmStatusProvider 范式）+
`DrainCommand`；MapServer 实现（draining 本地标记 + registry 心跳 + auth 守卫）。

## 二、交付内容

| 模块 | 说明 |
|---|---|
| `GmDrainHandlerInterface` / `DrainCommand`（framework，新） | drain 能力契约与 GM 命令（ok / error 两态，重复 drain 幂等 error）。 |
| `MapServer` | 实现 `GmDrainHandlerInterface`：`drain()`（draining 标记 + registry 心跳 status=draining）、`isDraining()`、`admissionRejection()`（draining → 'draining'；满员 → 'map_full'）；`handleAuthMessage` 入口在 token 消费**前置**拒绝（token 保留可重连其他频道——与 map_mismatch 不 consume 同口径）；注册 meta 携带 maxCapacity。 |
| `SocialService::selectChannel` | 路由过滤扩展：排除 status ∈ {stopping, draining} 的实例；排除 `playerCount ≥ maxCapacity`（声明时）的实例。 |
| `MapChannelFactory` | `NYTHROS_MAP_CAPACITY` env → MapServer maxCapacity；DrainCommand 装配进 GM 总线。 |
| `bin/verify-scale.php`（新） | 动态扩缩容 E2E（消费 P14 公共库）。 |

## 四、实测踩坑记录

- **会话频道优先 vs 最少在线的裁决顺序**：同图重入优先会话频道（ADR-015 登录确定性语义）——
  扩容新实例若要接客，必须先 drain 旧频道（会话偏好 outranks 最少在线）；E2E step3 首跑漏 drain
  即落回原频道，此裁决顺序已写进脚本注释。

## 五、边界与后续

- **autosciler 不在本批**：扩缩容的「决策何时扩/缩」是部署编排层关切（K8s HPA / 外部脚本观测
  registry meta 的 playerCount/status），engine 侧原语（注册/发现/过滤/drain）已齐备；bin/server 的
  `--parts` 与 deploy.yaml `count` 支持静态扩容声明。
- **容量语义**：maxCapacity 是硬顶（auth 拒绝 map_full）；软限流（排队/溢出转移到其他频道）需要
  网关侧排队原语，留待有真实部署需求时立项。
- draining 实例的存量玩家归零检测复用 map-rolling.php 的 watch 模式（registry meta 轮询），未新写编排。
