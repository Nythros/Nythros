3. **客户端生态为零**：仅 318 行 JS 协议参考客户端，无官方 SDK、无状态同步插值指南。
4. **无热更层**：玩法逻辑编译期固化；数值热载仅有 config.hot-reload（mtime 轮询）雏形。
5. **分布式不完整**：跨 map 实体迁移、动态扩缩容、跨服玩法原语缺位。
6. **遗留产品裁决项**：死亡掉落归属、PVP/安全区治理、AoE 多源归属统计。
7. **E2E 脆弱面**：验收脚本对时序/位置有假设；步骤失败时定时器不清理（依赖全绿）。

## 二、完善计划的总体原则

- 沿用试点验证过的模式：**框架出参数与规则（纯函数/只读配置），starter-kit 出装配与动作**，
  独立批次推进，每批 2–4 项、CI 四门禁 + E2E 三轮全绿、blueprint 验收记录。
- 优先级判断标准：**上手体验 > 玩法能力 > 规模化**——框架的消费方是人，先让「能开发」变成「好开发」。
- 需要产品输入的项（掉落比例、PVP 规则）先出参数草案再实现，避免拍脑袋。

## 三、完善路线（三阶段七批）

### 阶段 A：负载自适应与内容数据化（当前优先）

#### P9 批：负载感知动态 tick 与事件优先级降级（2026-08-29 新增立项）

需求来源：主程评审要求——AOI 世界按人数降频（20→5Hz）、全量房间按移动实体数降频（30→20Hz）、
**Hz 范围可配置**、**事件分级两层降级（关键帧极端情况才降，非关键帧优先降）**。

配置驱动（挂 ConfigRepository，支持热载，不发版调档）：

```yaml
tick_policy:
  cell_density:                  # AOI 世界：按格子密度（区域降频，非全图统一降档）
    base_hz: 20                  # 全局定时器恒定 base_hz，永不整体降档
    tiers: [ {until_players_in_cell: 12, hz: 20}, {until_players_in_cell: 25, hz: 10}, {hz: 5} ]
    neighbor_radius: 1           # 热区判定是否外扩邻接格
    hysteresis_seconds: 5        # 按格子滞回：人散后热区保持 N s 才降温
  move_broadcast_throttle:       # 热区内玩家移动广播节流（服务端合并，只发最新位置）
    hot_cell_hz: 5
  rooms:                         # 全量广播房间：三层模型（内层分频 / 进程预算 / 准入控制）
    base_hz: 30
    room_tiers: [ {until_entities: 40, hz: 30}, {hz: 20} ]   # 内层：房间自己实体数 → 期望档位
    process_budget:              # 进程层：多房间共享单 worker CPU 的预算池
      target_ms_per_tick: 8      # 单 base tick 全部房间允许消耗（按目标核占用反推，逐房间 hrtime 计费）
      min_hz_floor: 10           # 进程层降频地板；触地板仍超预算 → 准入层
      strategy: cost_first       # cost_first=最贵房间先降（回收最多） | uniform=全房间统一降档
    admission:                   # 准入层：分频到底仍超载 → 不再往本进程放新队伍
      max_rooms_per_process: 64  # 硬上限（registry 元数据对外报告）
      busy_threshold: 0.9        # 预算利用率 >90% → registry 标记 busy，匹配路由避开
  priority:
    critical: [combat:hit, combat:aoe, entity_dead, player:revive, quest:*]   # 任何情况不丢不迟
    normal:   [entity_moved(近/有仇恨), monster:spawned]
    low:      [entity_moved(远/无仇恨), drop:* 视野重同步, 采样]              # 第一层先降
```

**两层降级策略（本批核心设计）**：

- **L1 帧分级降载（Hz 不变，先动）**：复用 frameMerger 既有的 droppable 标记 / 软过滤 / 单帧字节配额，
  扩展优先级分类——low 档负载升高时先丢先合并；远处/无仇恨实体的 entity_moved 按 N 分频跳发（只保
  最新位置，客户端插值兜底）。
- **L2 区域/实体分频（主程对齐修正 2026-08-29：区域降频，非全图降档）**：全局定时器恒定 base_hz，
  每 tick 统计各 AOI 格子玩家密度（GridAOI 索引），超阈 cell（可含邻接格）标记热区——热区内实体的
  AI/移动广播按密度档位分频（20→10→5Hz，实体记上次更新时刻、dt 用真实流逝时间），非热区实体不受
  影响；全量房间为三层模型（主程对齐 2026-08-29：副本共享进程，仅按房间实体数定频会误判）——
  ① 房间内层：房间实体数 → 期望档位；② 进程预算层：逐房间 hrtime 计费，聚合超过
  target_ms_per_tick 时按 cost_first（最贵房间先降，回收最多）/uniform 降到 min_hz_floor，
  idle 房间 tick 开销趋零天然让出预算；③ 准入层：触地板仍超载则 registry 标记 busy（扩展
  roomCount/预算利用率指标），匹配路由避开本进程、新队伍落到空闲 worker，全部 busy 才排队/拒绝。
  滞回按格子做。关键帧（战斗帧）任何
  档位不丢不迟；玩家请求（attack/skill/move）为到达即处理、不随实体分频节流——其负载由 L1 优先级 +
  热区移动广播节流兜底，极端不足再议请求侧限流（P10 压测数据裁决）。

前置改造（无商量项）：**帧语义时间化**——攻击冷却（ATTACK_COOLDOWN_FRAMES）/出生保护
（SPAWN_PROTECTION_FRAMES）等帧计数改毫秒制；tick 分频器（基频细分 + 每 N 次触发）；dt 用真实
流逝时间；AI 每 tick 移 1 格在降档下的速度补偿（配置开关）。

协议与客户端：新增 tick 速率广播帧（world:tick_rate）；SDK/示例客户端插值窗口 = 1/当前档位；
entity_moved 事件驱动（玩家输入）与 tick 驱动（怪物/AI）分开插值。

双向自动调整（主程确认 2026-08-29）：密度每 base tick 重采样，档位纯推导、无状态锁存——降档需
「持续超阈 hysteresis_seconds」逐档下探，升档需「持续低于阈值」逐档回升至 base_hz；人走即回温。
两条实现保证：① fail-open——密度统计异常时全部实体回落 base_hz（故障方向必须「变贵」而非「变卡」）；
② 双向滞回 + 逐档步进，防临界抖动与频率锯齿。P10 压测将「降-升往返」列为正式验收项。

tiers 语义（主程对齐 2026-08-29）：阶梯式多档合法（如 20/15/10/5 四档），规则为「首个匹配档生效、
无界末档兜底」；加载期单调性校验（hz 须随密度非增，fail-fast）。注意判定维度是**格子密度**
（until_players_in_cell）而非全图总人数——全图维度即退化为全图降档。

跨档位邻接的已知副作用与缓解（无致命缺陷，安全性根基：战斗结算为事件驱动、与实体 tick 频率解耦）：
① 视野平滑度不对称（格界两侧玩家互看流畅度不同）→ 客户端插值兜底；② 怪物跨界档位突变顿挫 →
neighbor_radius 渐变带 + 移速补偿开关；③ 边界风筝倾向（拖怪到格界降其档位）→ 档位跟随当前格动态
自愈，可滥用时改为取邻接格密度最大值判定；④ AOI 索引时滞（热区实体索引滞后至多一个自身周期）→
周期性视野快照重同步（resyncVision）自愈。实现红线：时间语义全部真实流逝 dt；enter/leave 结构帧
与 critical 战斗帧永不因分频丢弃（L1 low 档仅含位置刷新类帧）。

已知边界（对主程的预期管理）：区域降频覆盖实体侧负载（怪物 AI、实体移动广播）；热区内玩家的
输入处理粒度随其所在格子档位变粗（5Hz 时 200ms，仅混战极端保底）；降频解决 CPU 与带宽的线性压力，
聚团混战的 O(N²) 广播本质边界由 P10 压测定量（玩家移动广播节流是流量大头的主要砍口）。
